# 叙事周期 · Narrative Radar

A股 / 美股公开证据研究与历史事件工作台。支持叙事关注度、人工观点标注、历史事件研究、观察池、主观情景与研究备忘录。原始黄金示例仍保留为 `index (1).html`。

这是**研究试用版**：已归档真实市场数据，但尚未具备完整机构投研、实时交易、团队权限、付费订阅或20–30年新闻全文覆盖。不会把缺失数据填成零分，不会把成交额标成资金净流入。

## 运行

应用只依赖 Python 3.12 标准库，无需 pip 安装或构建：

```sh
cd /workspace/gold-analysis
python3 -m radar.server --port 8088
```

启动时校验并导入已提交的真实历史子集；SQLite保存在 `.radar/radar.db`，也可通过 `RADAR_DB` 指定独立数据库。默认只监听127.0.0.1，适合个人研究；不要将这个无身份认证的开发API直接作为多租户生产服务。

## 已取得的实际数据

- 中国：上证综指、深证成指，1995-01起至2025-06；上证50、沪深300、中证500、创业板指按实际可用起点记录。
- 中国个股：平安银行、五粮液、贵州茅台、招商银行、山东黄金、比亚迪、宁德时代，起点按上市与可用日期，止于2025-08-06。**未复权收盘价格，不是含分红总回报**。
- 美国：标普500月度序列，1995-01至2026-09。历史段来自Shiller，上游2023-07起用FRED价格续接；不是美国全市场个股，也不能识别日内冲击。
- 共14组代表性序列。固定提交、文件SHA256、真实范围见 `data/history/manifest.json`。数据有历史时滞，不是盘中行情。
- 29个人工整理的事件锚点，包含政策、流动性、信用、科技和外生冲击。事件参考链接尚未全部自动核验；事后峰谷单独标记。

历史研究输出事件后的价格变化、完整窗口最大回撤与技术状态。日线研究从事件日期之后首个可用交易日收盘起算；月度研究从事件之后首个完整月的观察值起算。没有以这些结果声称因果效应、可交易策略收益或历史叙事热度。

## 数据连接器

实现了Fed、BLS、ECB、SEC公告、arXiv、Hacker News、GitHub采用情况、World Bank年度宏观、Stooq日线、东方财富日线和伯克希尔最新13F持仓。是否成功接入以**本次来源状态与实际归档记录**为准，代码存在不等于数据已取得。

在当前云实例，官方网络源受代理403限制，允许的GitHub历史归档已成功取得并校验。所需域名已加入环境配置草稿；GitHub Actions托管运行器会另行尝试采集并在公开站展示成功或失败状态。没有代理绕过或模拟数据回退。SEC可能要求有效的声明式联系信息，可在服务运行环境设置非秘密的 `RADAR_SEC_CONTACT`；不需要在代码中写API Key。

上交所、巨潮资讯、GDELT为**来源目录**，尚未实现历史归档连接器。N-PORT、实时机构资金流、交易执行与内部机构决策数据尚未接入。13F是延迟披露的持仓范围，value保留原文口径；不把持仓差分解释为实时交易。

## 评分

评分窗口为最近7天；至少3个去重标题、2个原始发布机构才显示热度。

- 热度：`100 × (0.55×关注量 + 0.25×来源广度 + 0.20×新鲜度)`。
- 共识：人工标注的支持/反证中占多数的一侧比例；至少3个独立标题且2个有标注的原始发布机构。同标题冲突标注排除。100也可能是一致反对。
- 证据置信度：来源权重 × 广度 × 样本覆盖。启发式覆盖指标，不是真实概率。

完整公式与限制在网站“评价方法”中。只进行同标题去重，尚不能可靠识别改写转载或还原原始信源独立性。没有当前新闻样本就不显示历史或实时热度。

## 公开部署

```sh
python3 -m scripts.build_site
python3 -m scripts.verify_site dist
```

生成 `dist/`，可部署到GitHub Pages等静态托管。`build_site` 使用独立构建数据库，**不会导出个人开发库中的笔记、观察池、判断、情景或导入证据**。公开站的私人工作簿保存在浏览器localStorage；不提供跨设备云同步。请导出工作簿自行备份。浏览器清理会移除本地笔记。

`.github/workflows/deploy.yml` 在main推送、手动触发或每日定时执行：单元测试 → 公共来源采集 → 隔离构建 → 资产校验 → GitHub Pages部署 → 外网HTTP/版本/历史数据验证。真实上线以部署工作流和外网验证结果为准；推送成功不代表发布成功。Pages首次启用与仓库权限可能受GitHub账户设置限制。

`RADAR_REFRESH_PUBLIC=1 python3 -m scripts.build_site` 会额外尝试更新公开来源，失败会记录实际状态。无需提供GitHub写入凭证给公开浏览器。

## 数据权利与商业化边界

中国历史仓库声明MIT；美国整理仓库声明ODC-PDDL，但上游原始数据与交易所商业再分发权未独立核验。来源许可说明与引用见 [DATA_SOURCES.md](DATA_SOURCES.md)。上线研究试用不表示已取得付费数据再分发许可。商业化仍需完成数据权利、持续覆盖与质量验收，以及团队身份、权限、审计、服务可靠性和实际用户付费验证。



## 数据验收（提案：方法 v1.1.0）

构建成功只证明静态产物生成。`python -m scripts.check_data_readiness dist`
另行检查 ai、china、power 三个核心主题：7日内至少3个标题簇、2个原始发布机构，
至少两个参与计算的机构在36小时内采集正常。逐主题失败原因写入 `data/readiness.json`。
行情要求 SPY、GLD、NVDA、沪深300、山东黄金有最近4个日历日以内的完整日线样本，
且本轮行情来源正常；此时效保护不是交易所日历，可用 `--expected-session US=YYYY-MM-DD`
和 `--expected-session CN=YYYY-MM-DD` 核验已知的最近交易日。中国长假期间须核实交易日，
不可通过扩大陈旧阈值宣称实时。

`data/score-inputs.json` 保存所有分数使用的14日完整输入，独立于界面最多500条的列表。
`audit` 保存窗口、输入ID、代表证据、机构分组、门槛和权重，可按快照时点重算。
热度缺失为 null；来源失败为 error/partial；空feed为 empty；合法feed没有主题命中为 no_match；
重复写入0条但已有合格命中的来源仍可为 ok。成交量实际为0时保留0，空值不填0。

GitHub cache 仅保存独立的 `.radar/build.db`；v2前缀避免复用旧分类缓存。
缓存不参与当前证据的日期判定；缓存被驱逐会冷启动并可能触发验收失败。
当前不能保证永久证据归档；持续运行后仍需可版本化的持久证据库。
未通过数据门槛时保留诊断产物，阻止新的公开产物进入部署步骤。
核心数据通过也只代表限定样本可用，不代表10主题齐备或投资结论有效。

新增官方RSS复用现有解析器；国家统计局、国家能源局使用有界列表及文章元数据适配器。
文章缺少发布日期或原始发布机构时拒绝计分。仅有日期时保留日期精度；只有整日区间完全落在评分窗口内才计入，新鲜度按整日最早时刻保守计算，不伪造具体发布时间。新接口必须在实际运行环境通过真实数据验收；
单元测试中的 fixture.invalid 为合成测试数据，禁止导入公开产物。

速度仅在本周与上周都达到3标题簇/2发布机构时计算，保留负值；相等样本才为真实0，基期不足为null。无证据时新鲜度为null。v1.1.0与v1.0.0不应直接拼接为同口径时间序列。
